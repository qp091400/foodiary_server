# 식사 인원과 개인화 레시피

`0016` 마이그레이션을 먼저 적용한다. `users.household_size`는 1~20의 정수이며 기존 계정은 NULL로 유지한다. 새 가입의 `household_size`는 필수이고, 기존 계정은 `PATCH /users/me`로 변경한다. 내 계정 응답에만 제공하며 공개 프로필에는 노출하지 않는다. 앱에서는 1인·2인·3인·4인 이상으로 선택하고, 4인 이상은 실제 인원을 필수로 입력한다.

## 검색과 추천 API

`POST /fridges/{id}/recipes/recommendations`의 기존 `item_ids`, `offset`, `seed`에 다음을 추가했다.

- `q`: 최대 100자. 요리 이름·분류·조리법·재료 이름의 기본 검색. 공백으로 나눈 단어를 모두 포함해야 하며 계란/달걀, 쇠고기/소고기를 동일하게 처리한다. 검색은 식품 선택 없이도 가능하고, 식품을 선택했다면 기존의 모든 선택 재료 포함 조건을 유지한다.
- `profile_version`: 다음 페이지를 요청할 때 첫 응답의 값을 보낸다. 중간에 인원이나 후기가 바뀌면 409로 새로고침을 안내하여 페이지 중복·누락을 막는다.

응답에 `household_size`, `profile_version`, `preference_review_count`, `query`가 추가된다. 각 추천에는 `recommendation_reasons`, `preference_evidence`, `target_servings`, `source_servings`, `original_servings`, `portion_note`가 있다. `preference_evidence`는 로그인한 본인의 후기 ID·요리·별점·일치 특성을 제공한다.

## 학습 기준

신경망 재학습이나 임베딩 호출이 아닌, 본인의 최근 후기 최대 100개를 요청 시 다시 읽는 설명 가능한 내용 기반 점수다. 다른 사람의 평점 평균은 카드에 표시만 하고 개인 취향 학습에는 사용하지 않는다. 삭제한 후기와 `[시연용`, `[검색 시연용`으로 시작하는 가상 후기는 제외한다. 후기 수정·삭제와 인원 변경은 다음 추천 요청부터 반영된다.

별점 1·2·3·4·5점은 해당 요리의 비양념 재료·분류·조리법·특징에 각각 -2·-1·0·+1·+2점을 준다. 매콤·담백·바삭·고소·국물·간편이라는 특징에 대한 명확한 좋아함/싫어함 문구도 보조 점수로 사용한다. 이 문구 처리는 제한된 규칙이며 모든 한국어 감정·부정을 이해하지 않는다. 특성별 누적 영향은 ±4로 제한한다.

선택 재료 포함 여부와 부족한 재료 수, 단계별 설명 유무를 먼저 지키고, 그 안에서 취향 점수와 원본 인분의 근접도를 반영한다. 동점은 요청별 seed로 섞고 같은 요리의 변형은 묶는다. 학습 이력이 없으면 재료 기준 추천을 설명한다. 긍정적인 추천 근거에는 실제 본인 후기의 별점과 요리 이름을 표시한다.

## 인분과 재료 양

명확한 `N인분` 원본만 실제 식사 인원으로 환산한다. 상세의 재료 수량 중 단일 숫자·분수와 알려진 단위만 비례 계산하고 `original_text`, `amount_adjusted`로 원문과 계산 여부를 구분한다. 약간·취향껏·범위·복합 포장 수량은 그대로 둔다. 원본 인분이 없으면 임의로 추정하지 않고 안내한다. 조리 시간·온도·조리법은 자동 배수 계산하지 않는다.

검증: `tests/test_personal_recipes.py`, 앱 `tests/personal-recipes.test.mjs`. 색인·기본 자료 경로, 개인별 분리, 페이지 순서, 후기 변경, 인분 불명확성과 원본 보존을 검사한다.
