# 커뮤니티 글 검색 · 후속 구현 안내

`GET /posts?q=달걀&board=recipe&limit=20`으로 로그인 후 검색한다.

- `q`: 최대 100자. 앞뒤 공백을 제외한 **문자열 전체**가 제목 또는 본문에 포함된 글을 반환한다. 영문 대소문자를 구분하지 않는다. `%`, `_` 등의 문자는 와일드카드가 아닌 실제 문자로 취급한다.
- 빈 검색어·공백·파라미터 생략은 기존 목록 조회와 같다. `board`를 생략하면 전체 게시판, 지정하면 해당 게시판 안에서 검색한다.
- 최신순이며 응답은 기존 `{posts, next_before_id}` 그대로다. 더 보기를 요청할 때 같은 `q`, `board`와 반환된 `before_id`를 함께 보낸다.
- 삭제된 글은 제외한다. 일반 글과 자동 등록된 레시피 후기 모두 검색된다. 수정·삭제는 즉시 다음 검색에 반영된다.
- DB 스키마 변경, 임베딩 생성, 외부 API나 추가 의존성은 없다.

## 임베딩 검색을 붙일 위치

검색 구현은 `app/services/post_search.py`의 `find_posts()` 한 곳에 둔다. 라우터는 요청 검증과 기존 `_decorate()` 응답 조립을 담당하고, 앱은 검색 방식과 무관하게 같은 API를 호출한다. 지금은 별도 검색 엔진 인터페이스나 설정을 만들지 않았다.

임베딩 구현 시 이 함수 안의 검색 조건을 교체·확장할 수 있다. 삭제 제외·게시판 필터·로그인 보호를 유지해야 한다. 현재 페이지 기준은 `id DESC` + `before_id`이므로, 유사도 순으로 정렬하려면 그 정렬에 맞는 커서를 추가해야 한다. 검색 인덱스를 별도로 운영한다면 글·후기 생성, 수정, 삭제에 따른 인덱스 동기화도 후속 구현에 포함한다.

앱 연결은 `src/features/service/community-model.ts`의 `postsPath()`와 `community.tsx`의 검색 입력·적용 검색어 상태에 있다. 검색 버튼 또는 키보드의 검색/Enter로 실행하며, 초기화 버튼으로 원래 목록으로 돌아간다. 게시판 변경·더 보기·새로고침 중에도 적용된 검색어를 유지한다.

검증: `tests/test_community.py`, `tests/test_recipe_reviews.py`, 앱의 `tests/community-boards.test.mjs`.
