# 2026-11-01 식사 인원 기능 제거

가입 시 인원 입력, 내 정보 설정, 인원에 따른 추천 순서, 인분·재료 양 자동 환산과 관련 API 필드를 제거했다. 레시피 검색과 본인의 별점·후기 기반 취향 점수·근거 표시는 유지하며 원본의 인분·재료 양을 표시한다.

- 서버 `foodiary-00031-n8j` 및 비공개 푸시 작업: `asia-northeast1-docker.pkg.dev/virtual-primer-512512-g0/foodiary/foodiary@sha256:e434e3deb18afd0acc547c936c8fea281740fcabe028ee2d81bc2f39099e1548`.
- 새 서버로 트래픽 100% 전환을 확인한 뒤 이전 요청의 최대 처리 시간 180초 이상을 기다리고, 이전 푸시 작업이 실행 중이지 않은 것을 확인했다.
- 이후 마이그레이션 작업으로 `0016 -> 0017` 실행 성공. 인원 칸과 제약만 삭제하며 계정·냉장고·게시글·후기는 보존한다. 이미 적용된 0016 이력 파일은 새 환경의 연속 마이그레이션을 위해 유지한다.
- Firebase `foodiary-35981` / `foodiary-app-ef2b5` 웹 배포 완료. API와 작업의 기존 환경·비밀 참조·공개 범위를 보존했다. 푸시 작업도 실행 성공했다.

검증: 관련 서버 128개, Linux 배포 이미지 전체 955개 통과. 앱 타입 검사·린트 및 전체 165개 통과. SQLite에서 0017 적용 후 기존 계정·게시글 보존과 모델 일치, PostgreSQL 대상 삭제 SQL을 확인했다. 실제 레시피 색인의 선택 재료 추천·검색 검사도 통과했다.

운영 가입 API의 필수 입력에서 인원 항목이 빠진 것을 확인했다(빈 요청만 사용해 가입·메일 발송 없음). DB 정리 후 준비 상태 200과 인증 보호·내부 문서 비공개 검사가 통과했다. 홈·가입·내 정보·알림 HTML과 워커, 실행 JS 9개의 SHA-256이 배포본과 일치하며 인원 필드가 포함되지 않는 것을 확인했다.

되돌리기 순서는 [personal-recipes.md](personal-recipes.md)를 따른다. 이전 API 이미지는 DB의 인원 칸을 읽으므로 0017 상태에서 바로 재배포하지 않는다.
