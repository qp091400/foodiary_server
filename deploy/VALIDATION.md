# 배포 준비 검증 기록

검증일: 2026-10-21. Oracle 계정과 실제 VM은 아직 없으며, 아래 검증은 로컬 Windows/WSL Docker에서 수행했다.

## 모델과 실행 환경

- Python 3.11 Docker 운영 이미지의 Linux ARM64 빌드와 패키지 설치 성공.
- ARM64는 x86 PC의 QEMU 에뮬레이션으로 실제 PaddlePaddle 3.2.2 추론을 실행했다.
- PaddleOCR 3.7.0 / PaddleX 3.7.2, CPU 2스레드, 세 모델의 검출·방향·인식 시험 성공.
- 모델은 `PP-OCRv5_server_det`, `korean_PP-OCRv5_mobile_rec`, `PP-LCNet_x1_0_textline_ori`.
- 실제 내려받은 모델 파일 9개의 SHA256은 `model-manifest.json`에 기록했다. 파일 검증도 통과했다.
- 패키지 96개 버전은 `constraints-production.txt`로 고정했다.

ARM 에뮬레이션 시작 검사는 약 151초, 프로세스 최대 RSS 약 1,833MiB였다.
이 수치는 에뮬레이터와 모델 초기화를 포함하며 실제 Oracle A1의 속도·메모리 보장이 아니다.

## 영수증 파이프라인

같은 모델 파일을 사용하는 네이티브 x86_64 컨테이너에서 한글 합성 영수증을 검사했다.
`scripts/create_test_receipt.py`로 재생성할 수 있다. 개인 영수증을 사용하거나 외부 AI에 이미지를 보내지 않았다.

| 품목 | 수량 | 단가 | 금액 |
|---|---:|---:|---:|
| 서울우유 1L | 1 | 2,980 | 2,980 |
| 풀무원 두부 | 2 | 1,500 | 3,000 |
| 물티슈 100매 | 1 | 1,000 | 1,000 |

3개 품목과 합계 **6,980원**, 구매일 **2026-10-21**을 기대값과 비교하여 확인했다.
초기화 포함 약 22.8초, 프로세스 최대 RSS 약 4,700MiB였다.
작은 메모리 요금제를 충분하다고 가정하지 않는 이유다. 사진 크기와 내용에 따라 메모리가 달라진다.

## API·데이터

- 기존 테스트와 추가 운영 보안 검사를 합쳐 239개 통과.
- PostgreSQL 16에 Alembic 마이그레이션 적용 성공, 현재 모델과 차이 없음.
- PostgreSQL 동시 먹음/버림 검사: 응답 200/400, 1개·1,000원만 기록. 중복 차감 방지 확인.
- Caddy 운영 설정 문법 검증 성공.
- Caddy 경유 로컬 HTTP 통합 검사: `/ready` 200, 인증 없는 `/fridges` 401, 문서·개발 경로 404.
- 서로 다른 X-Forwarded-For를 위조해도 인증 요청 제한 429가 적용됨을 확인했다.
- API/DB 호스트 포트 미게시와 비root·읽기 전용 컨테이너 설정을 검사했다.
- 네이티브 운영 API + 실제 모델 + PostgreSQL로 사진 업로드(201) → 초안 3줄 → 확정 2개 식품/비식품 1줄 제외 → 식품 5,980원·비식품 1,000원 통계 반영까지 확인했다.
- 백업 스크립트로 만든 DB 덤프를 별도 PostgreSQL DB에 복구하여 영수증 1건과 이미지 1개를 확인했다.
- 배포 압축본을 다시 풀어 빌드한 이미지에 환경설정·개인키·백업 검사 파일이 포함되지 않는 것을 확인했다.
- 운영 이미지의 비root UID 10001, 읽기 전용 루트 파일시스템에서 모델 추론 성공.
- `pip-audit`로 고정 의존성을 검사했으며 알려진 취약점이 보고되지 않았다.

## 실제 배포 때 남은 검증

- Oracle 계정 생성, Always Free 대상·자원 확보·네트워크 설정.
- 실제 A1에서 시작 검사와 실제 촬영 영수증의 정확도·속도·최대 메모리 측정.
- 공인 DNS 및 HTTPS 인증서 발급과 외부에서의 API 점검.
- 실제 SMTP 인증 메일 도착, 회원가입부터 영수증 확정까지 휴대폰으로 점검.
- 서버 외부 백업과 복구 절차 확인.

합성 이미지 통과는 실제 마트 사진의 인식 품질이나 서비스 보안 전체를 보장하지 않는다.
