# Cloud Run 배포 준비 검증

로컬 검증일: 2026-10-21. 실제 Google Cloud 계정 검증일: 2026-10-23(아래 "실제 계정 검증" 참고).

## 통과한 로컬 검증

- 기존 기능·운영 보안·Cloud Run 배포 검사를 합쳐 **255개 테스트 통과**.
- `cloudrun` Docker 타깃을 Linux x86_64/Python 3.11에서 빌드했다.
- 빌드 과정에서 실제 검출·방향·한글 인식 모델을 실행한 후 파일 9개를 기존 SHA256과 비교하여 이미지에 포함했다.
- 컨테이너의 외부 네트워크를 끈 상태에서도 이미지 내 모델로 실제 시작 추론 성공. 기본 크기 시작 검사는 약 6.9초, 프로세스 최대 RSS 약 1,639MiB였다.
- 새 PostgreSQL 16 DB에 별도 Alembic 명령으로 마이그레이션 성공. API 시작 프로세스에서는 마이그레이션하지 않는다.
- 외부 통신이 차단된 Docker 내부 네트워크에서 CPU 2개·RAM 8GiB 제한의 실제 운영 API를 실행했다.
- API 사용자 10001, API·DB 호스트 공개 포트 없음, 업로드 볼륨 필수 검사와 쓰기·삭제 시작 검사 성공.
- 인증 없는 냉장고 접근 401, 문서/개발 경로 404, 허용하지 않은 Host 400, HSTS 등 보안 헤더 검사 성공.
- 서로 다른 클라이언트와 위조한 전달 IP 헤더에서도 인스턴스 전체 요청 제한을 공유하는 테스트 통과.
- 인증 후 한글 합성 영수증 업로드 201 → 초안 3품목·합계 **6,980원** → 확정 시 식품 2개·비식품 1개 제외 확인.
- API를 종료하고 새 컨테이너로 만들었을 때 동일 DB와 업로드 볼륨에서 확정 영수증 1건·식품 2개·사진 1개 유지 확인.
- 이 사진 요청은 약 **16.8초**, 컨테이너 전체 최고 메모리는 약 **5,492MiB**였다. WSL의 로컬 x86_64 측정값이며 Cloud Run 속도·메모리 보장이 아니다.
- 실제 Google Cloud SDK 590.0.0에서 서비스·마이그레이션 작업의 명령 인자가 해석됨을 확인했다. 자격 증명과 네트워크 없이 실행해 인증 전에 중단되도록 했으며 실제 배포 성공을 뜻하지 않는다.
- 실제 gcloud 소스 업로드 목록에서 환경설정·키·개인 설정·사진·백업이 제외되고 빌드 파일이 포함되는지 검사했다.
- 배포 압축본을 새 폴더에 풀고 루트/중첩 경로에 가짜 비밀 파일을 넣은 뒤 실제 gcloud 목록과 재빌드한 Docker 이미지에서 모두 제외됨을 확인했다.
- 모델 파일을 root 소유로 복사해 런타임 사용자 10001이 수정할 수 없음을 검사했다. 최종 소스로 재빌드한 이미지에서도 네트워크 없이 한글 영수증 3품목·6,980원 인식이 성공했다.

합성 영수증의 품목별 금액은 우유 2,980원, 두부 3,000원, 물티슈 1,000원이다.
`OCR_DET_MAX_SIDE=1280`에서 우유 상품명 중간 공백은 빠졌으나 수량·단가·금액·용량은 맞았다.
실제 마트 촬영 사진의 품질을 입증하는 검사는 아니다.

## 실제 계정 검증 (2026-10-23)

시험용 Google Cloud 프로젝트, 도쿄 `asia-northeast1`, Neon Free(AWS 싱가포르, 직접 연결)에서 확인했다.

통과한 것:

- 청구 계정 연결, Google AI Pro 월 크레딧 적용, 월 예산 알림(크레딧 제외 기준, 50/80/100%).
- `setup`, `secrets`(Secret Manager 3개), `build`(Cloud Build, 3분 53초), `migrate`(테이블 11개), `deploy`(첫 리비전), `verify`(비공개 Google 인증 검사) 모두 성공.
- Neon TLS 연결과 마이그레이션. 이미지 안의 모델로 서비스 시작 OCR 검사가 통과해 서비스가 시작됨.
- 사진 버킷 마운트: 영수증 업로드 후 버킷에 사진 파일이 저장됨(쓰기 확인).
- 실제 SMTP: 인증 메일이 도착함. 회원가입, 냉장고 자동 생성, 영수증 업로드 → 초안(3품목, 합계 6,980원, 로컬과 동일) → 확정(식품 2개, 비식품 제외) → 목록·월별 통계, 초안 삭제 확인.
- DB 행(사용자·영수증·식품)이 Neon에 저장됨.

측정값(합성 영수증 1종, 서버가 켜진 상태에서 2회 확인, 실제 사진 아님):

- 영수증 한 장 인식 요청에 약 31~32초. 로컬 Docker(약 17초)보다 느리다.
- OCR이 도는 동안 다른 업로드는 의도한 대로 `503`(분석 중)을 받았고, 가벼운 `DELETE` 요청 하나가 앱 로그 없이 `429`를 받았다. 원인은 확인하지 않았다(최대 인스턴스 1과 관련 가능성).

아직 하지 않은 것:

1. 실제 촬영 영수증의 인식 정확도.
2. 콜드 스타트 시간, 최고 메모리, 일별 청구액.
3. 서버 재시작 후 사진·데이터 보존(사진은 버킷, 데이터는 Neon에 있는 것만 확인함), Neon 절전 후 재연결.
4. 실제 휴대폰 앱으로의 시험(공개 자체는 2026-10-24에 완료: 토큰 없이 `/ready` 200, `/fridges` 401, 문서·개발 페이지 404, 보안 헤더 확인).
5. DB/사진 외부 백업과 실제 복원.

무료 한도·크레딧·최대 인스턴스 수는 총 지출을 차단하지 않는다. 현재 상태는 2026-10-24부터 공개 배포이며 회원가입이 열려 있다. 마트 영수증 정확도는 아직 시험하지 않았다.
